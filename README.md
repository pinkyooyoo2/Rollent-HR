# ROLLENT 인사평가 관리 시스템

대양롤랜트(주) 관리자용 인사평가 웹앱입니다. 자기평가 → 팀장평가 → 임원평가 → 최종 확정까지의 전 과정을 관리합니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | React 18 + TypeScript + Tailwind CSS 4 (Vite), React Router, Recharts, PapaParse, jsPDF + html-to-image |
| 백엔드 | Node.js 24 + Express 4 + TypeScript (tsx 실행), zod 입력 검증, helmet |
| 데이터베이스 | SQLite (Node 24 내장 `node:sqlite`, 네이티브 빌드 불필요) / SQL 마이그레이션 |
| 인증 | 사번 + 비밀번호(bcrypt 해시), HttpOnly·SameSite=Strict 세션 쿠키, CSRF 헤더 검증 |

## 실행 방법

필요 조건: **Node.js 24 이상** (`node:sqlite` 사용)

```bash
npm install
cp .env.example .env        # 선택 (기본값으로도 동작)
npm run db:reset            # 마이그레이션 + 샘플 데이터 생성 (기존 DB 삭제)
npm run dev                 # API(4000) + 웹(5173) 동시 실행 → http://localhost:5173
```

운영 모드:

```bash
npm run build               # 타입 검사 + 프론트엔드 빌드 (client/dist)
npm start                   # http://localhost:4000 에서 API와 빌드된 화면을 함께 제공
```

| 명령 | 설명 |
|---|---|
| `npm run db:migrate` | 미적용 마이그레이션(`server/src/db/migrations/*.sql`)만 적용 |
| `npm run db:seed` | 비어 있는 DB에 샘플 데이터 생성 |
| `npm run db:reset` | DB 파일 삭제 후 마이그레이션 + 샘플 데이터 재생성 |
| `npm run typecheck` | 프론트/백엔드 타입 검사 |
| `npm run test:api` | API 통합 테스트 (별도 `data/test.db` 사용, 152개 항목) |
| `node scripts/check-i18n.mjs` | 5개 언어 사전의 키·자리표시자 누락 점검 |

## Render 배포

저장소에 포함된 `render.yaml`(Blueprint)로 배포합니다.

1. 이 폴더를 GitHub(또는 GitLab) 저장소에 올립니다. `data/`(DB), `.env`, `node_modules`, `client/dist` 는 `.gitignore` 로 제외됩니다.
2. Render 대시보드 → **New → Blueprint** → 저장소 선택 → `render.yaml` 내용 확인 후 **Apply**.
3. 첫 배포가 끝나면 `https://<서비스명>.onrender.com` 으로 접속합니다. 처음 시작할 때 DB가 비어 있으면 샘플 데이터(관리자 / Admin 등)가 생성됩니다.

| 설정 | 값 | 설명 |
|---|---|---|
| Build | `npm ci --include=dev && npm run build` | 빌드 도구가 devDependencies 에 있어 함께 설치 |
| Start | `npm run db:seed && npm start` | 미적용 마이그레이션 적용 → DB가 비었을 때만 샘플 생성 → 서버 시작 |
| 영구 디스크 | `/var/data` (1GB), `DB_PATH=/var/data/hr.db` | SQLite 파일 보관. **유료(starter 이상) 인스턴스에서만 사용 가능** |
| `NODE_VERSION` | 24.19.0 | Node 24 내장 SQLite 사용 |
| `COOKIE_SECURE` | true | HTTPS 전용 쿠키 |
| `TRUST_PROXY` | 1 | Render 프록시 뒤의 실제 접속 IP 로 로그인 시도 제한·접근 로그 기록 |
| Health check | `/api/health` | |

- **무료 플랜:** 영구 디스크를 쓸 수 없어 재배포·재시작(15분 미사용 후 절전 포함)마다 DB가 샘플 데이터로 초기화됩니다. 시연용으로만 쓰세요.
- **기존 로컬 데이터 옮기기:** 배포 후 Render Shell 에서 `/var/data/hr.db` 를 로컬 `data/hr.db` 로 교체할 수 있습니다(서비스 중지 후). 그렇지 않으면 샘플 데이터로 시작합니다.

## 로그인 방식 / 샘플 계정

**아이디 = 이름, 비밀번호 = 사번**입니다. 관리자 페이지에 등록된 직원 계정의 이름·사번과 대조하며, 별도의 비밀번호 설정·변경·찾기 기능은 없습니다(사번이 곧 비밀번호).
- 사번은 사람마다 다르므로 동명이인도 이름 + 사번으로 정확히 구분됩니다. 직원의 사번을 바꾸면 바뀐 사번으로 로그인합니다.
- 로그인 후 **관리자는 관리자 페이지**, **임원·팀장·팀원은 평가 전용 사이트(`/e`)**로 바로 이동합니다.
- 이름은 앞뒤 공백을 무시하고, 사번은 앞뒤 공백과 영문 대소문자를 구분하지 않습니다.
- 5회 연속 실패 시 15분 잠금, IP 단위 요청 제한은 그대로 적용됩니다.
- 직원 상세 → 계정에서 역할과 사용 여부만 정합니다(계정을 비활성화하면 로그인할 수 없음).

**역할별 확인용 계정** (`server/src/db/demoAccounts.ts`, 진행 중 차수에서 세 사람이 서로 평가하는 한 팀으로 배정)

| 화면 | 아이디(이름) | 비밀번호(사번) | 평가 |
|---|---|---|---|
| 관리자 페이지 | 관리자 | `Admin` | 관리자 페이지 전체 (보정·확정·결과 CSV 승인 포함) |
| 팀원 페이지 | 팀원 | `A000` | 자기평가 · 팀장평가(→ 팀장) |
| 팀장 페이지 | 팀장 | `A0001` | 자기평가 · 팀원평가(→ 팀원) |
| 임원 페이지 | 임원 | `A0002` | 자기평가 · 팀장평가(→ 팀장) · 팀원평가(→ 팀원) |

- 이미 쓰던 DB에 이 계정을 반영하려면 `npm run db:demo-accounts` 를 실행합니다(예전 샘플 관리자·확인용 계정은 이름·사번만 바꾸고, 없으면 생성·배정. 여러 번 실행해도 같은 결과).
- '순차 진행'이 켜진 차수에서는 팀원이 자기평가를 제출해야 팀장의 팀원평가가 열리고, 팀장평가가 제출되어야 임원의 팀원평가가 열립니다(평가 진행 관리에서 끌 수 있음).
- 그 밖의 샘플 직원(김대양 / `E0001`, 최수진 / `R1001`, 정민호 / `R2001` 등)도 같은 규칙(이름 / 사번)으로 로그인합니다.

결과 CSV 승인은 업로드한 관리자와 **다른 관리자**만 할 수 있으므로, 이 기능을 쓰려면 관리자 계정이 2개 이상 필요합니다.

## 평가 전용 사이트 (팀원·팀장·임원, `/e`)

관리자 페이지와 같은 로고·색상을 쓰며, HOME·사이드바·통계 없이 **평가 유형 탭 → (대상이 여러 명이면) 대상 선택 → 작성 → 최종 제출** 흐름만 제공합니다.

| 역할 | 탭 | 평가 유형(저장 구분) | 불러오는 평가항목 |
|---|---|---|---|
| 팀원·차장 | 자기평가 / 팀장평가 | 자기평가 / 팀원→팀장평가 | 자기평가 / 팀원→팀장평가(공통) |
| 팀장 | 자기평가 / 팀원평가 | 자기평가 / 팀장→팀원평가 | 자기평가 / 팀장평가 |
| 임원 | 자기평가 / 팀장평가 / 팀원평가 | 자기평가 / 임원→팀장평가 / 임원→팀원평가 | 자기평가 / 임원평가 |

- **화면 표시 항목:** 회사 로고, 평가 유형, 대상자 이름·부서·직급, 마감 D-DAY(D-7·D-3·D-1·D-DAY·마감, 남은 일·시간), 질문과 응답 입력, 자동저장 상태, 최종 제출, 언어 선택(5개 언어), 로그아웃
- **자동저장:** 마지막 입력 2초 후 서버 DB에 저장합니다.
  - 저장 상태를 "저장 중… / 모든 변경사항 저장됨 / 저장 실패 / 마지막 저장 시각"으로 표시합니다.
  - 요청마다 증가하는 순번을 보내, 늦게 도착한 이전 요청이 최신 응답을 덮어쓰지 못하게 서버에서 막습니다.
  - 네트워크 오류가 나면 **탭을 닫으면 사라지는 sessionStorage**에 임시 보관하고 자동으로 다시 시도합니다(온라인 복귀 시 즉시). 저장되면 임시본을 지우고, 로그아웃할 때도 모두 지웁니다.
  - 새로고침·페이지 이동·재로그인 후에도 이어서 작성할 수 있습니다.
- **최종 제출:** 필수 응답 검증 → 남은 변경 저장 → 확인 창 → 제출 순서로 진행하고, 제출 시각을 기록합니다. 이후에는 수정할 수 없고, 관리자가 재오픈하면 다시 수정할 수 있습니다(재오픈 이력 저장).
- **제출 완료 화면:** 제출 일시와 남은 평가 바로가기를 보여주고, 모두 끝나면 "모든 평가를 제출했습니다"와 로그아웃을 표시합니다. **점수나 결과는 표시하지 않습니다.**
- **마감:** 평가 유형별 마감일을 둘 수 있고(평가 진행 관리 → 차수 수정, 비우면 차수 종료일), 마감일 23:59:59(`TZ_OFFSET`)까지 작성할 수 있습니다. 마감 여부는 서버 시간으로 판정합니다.
- **양식 버전:** 처음 저장할 때 그 시점의 게시 양식 버전으로 고정되므로, 관리자가 새 버전을 게시해도 작성 중이거나 제출된 응답은 손상되지 않습니다.
- **정보 접근 제한 (서버 검증):** 평가 사이트 API(`/api/eval`)는 본인이 평가자인 배정만 다룹니다. 다른 사람의 배정 ID 를 넣으면 404를 반환합니다.
  - 대상자 정보는 이름·부서·직급만 보냅니다.
  - 점수·가중치·결과·다른 평가자의 응답·대상자의 자기평가 내용은 보내지 않고, 제출된 평가는 응답도 다시 보여주지 않습니다.
  - 임원·팀장·팀원 계정은 관리자 API(직원·결과·리포트·KPI·가중치 등) 호출 시 403을 받습니다.

부서는 **관리직(OFF)·생산직(PRD)** 2개이며, 부서는 추가·수정만 가능하고 삭제 기능은 없습니다. 직원 데이터는 모두 **샘플**입니다. 팀/사원관리 → CSV 관리에서 실제 CSV로 교체할 수 있습니다(템플릿 다운로드 제공).

직급은 **임원 / 팀장 / 차장 / 팀원** 4단계이며 직원 수정 창에서 바꿀 수 있습니다. 직급이 임원·팀장이면 팀장&임원용 평가 양식, 차장·팀원이면 팀원용 양식이 적용됩니다. 부서 관리에서 부서 팀장(팀장평가 평가자)으로 지정하면 직급도 팀장으로 바뀝니다.

## 첨부 평가표 반영 내용

`server/src/db/formTemplates.ts`에 5개 PDF를 그대로 옮겨 두었습니다.

- 양식 4종(관리직-팀원, 관리직-팀장&임원, 생산직-팀원, 생산직-팀장) × 평가 유형 3종(자기/팀장/임원) = 12개 양식, 각 100점
- 점수 체계: A 5점 ~ E 1점, 평정요소 배점은 문항 수로 균등 분배 (예: 고객만족 7점 / 4문항 = 1.75점)
- 자기관찰 항목(업무의 양·난이도 등)은 점수 미반영 객관식, 건의사항은 양식 마지막 "기타 건의사항"(점수 미반영)
- 가중치: 팀원 양식 1차 20% / 2차 40% / 3차 40%, 팀장 양식 20% / 80% / 0% → 팀장 대상자의 2차 평가자는 임원으로 해석해 **자기 20 / 팀장 0 / 임원 80**으로 직군별 가중치를 설정 (가중치 0% 단계는 "해당 없음")
- 첨부 파일에 없는 질문은 만들지 않았습니다. 편집기에서 "샘플 문항" 표시로 구분해 추가할 수 있습니다.

## 점수 계산

1. 평가 1건 점수 = Σ(문항 득점 비율 × 배점) / Σ배점 × 100 (100점 정규화)
2. 개인 환산점수(가중 합산) = 자기 × w자기 + 팀장 × w팀장 + 임원 × w임원 (가중치 합 100% 검증)
3. 부서 KPI (부서 KPI 관리 메뉴, 차수별)
   - 지표는 화면에서 직접 입력하거나 "파일 업로드" 탭에서 CSV(부서명, 지표명, 단위, 평가방향, 목표, 실적, 가중치)로 한 번에 등록·수정·되돌리기 할 수 있음. 현재 KPI는 CSV로 내보내 수정 후 다시 올릴 수 있음
   - 지표 달성률: 높을수록 좋음 = 실적 ÷ 목표 × 100, 낮을수록 좋음 = 목표 ÷ 실적 × 100
   - 지표 점수 = min(달성률, 100), 부서 KPI 환산점수 = 지표 점수의 가중 평균
   - 목표 또는 실적이 0(미입력)인 지표는 계산에서 제외
4. 계산 점수 = KPI 반영 시 개인 환산점수 × 개인% + 부서 KPI × KPI% (기본 80/20), KPI 미반영이거나 소속 부서에 계산 가능한 KPI가 없으면 개인 환산점수
5. 필수 단계 중 미제출이 있으면 **0점이 아니라 "미완료"** 로 표시
6. 최종 점수 = (확정 시 고정 값) ?? 최신 유효 보정 점수 ?? 계산 점수
7. 가중치·KPI를 바꾸면 미확정 결과는 즉시 재계산됨

예: 자기 90 / 팀장 80 / 임원 85, 가중치 20/40/40 → 개인 **84점**. 관리직 KPI 96.5점, 80/20 반영 → **86.5점** (API 테스트로 검증됨)

점수 보정은 관리자·임원이 결과 화면의 점수 옆 연필 버튼으로 새 점수를 직접 입력합니다(예: 60 → 90). 사유는 선택이며, 보정 전·후 점수와 보정자·시각은 이력에 남고 취소할 수 있습니다. 최종 확정된 결과는 재오픈 후에만 보정할 수 있습니다.

개인별 결과 리포트는 응답&결과 → 평가 결과 목록의 각 행(또는 상세 창)에서 PDF·CSV로 바로 내려받습니다.

## 보안

- 로그인: 이름 + 사번 서버 대조, 5회 실패 시 계정 15분 잠금, IP 단위 요청 제한
- 세션 토큰은 해시만 저장, HttpOnly + SameSite=Strict 쿠키, 상태 변경 요청은 `X-Requested-With` 헤더 필수
- 직원 삭제는 소프트 삭제(과거 평가 보존, 계정 비활성화). 사번은 UNIQUE
- 모든 관리 작업은 `activity_logs`, 모든 API 호출은 `access_logs`에 기록. 보정·확정·재오픈 이력은 별도 테이블로 영구 보존

## 미구현 / 제한 사항

- **로그인 보안:** 비밀번호가 사번이므로 다른 사람의 이름과 사번을 아는 직원은 그 사람으로 로그인할 수 있습니다(요청에 따른 운영 방식). 사번이 사내에 공개되는 환경이라면 운영 전에 위험을 검토하세요.

- **팀원→팀장평가 익명성:** 팀장에게는 공개되지 않지만, 관리자는 평가자별 응답을 열람할 수 있습니다(평가자 관리 화면). 완전 익명 처리는 하지 않았습니다.
- **팀원→팀장평가 반영 비율 기본값 0%:** 응답은 수집하지만 최종 점수에는 반영하지 않습니다. 반영하려면 평가항목 → 평가 가중치에서 팀장 직군에 비율을 지정하세요.
- **임원 직군 변경:** 이미 마감된 2025 차수는 기존 기록을 그대로 두었고, 진행 중인 2026 차수부터 임원은 자기평가만 적용됩니다(임원 대상 팀장·임원평가 배정과 그 응답은 마이그레이션에서 제거).
- **PDF**: 브라우저가 화면을 이미지로 캡처해 만듭니다(한국어·러시아어 글꼴 깨짐 없음). 그래서 PDF 안의 텍스트는 선택하거나 검색할 수 없습니다. 출력은 시스템 글꼴(Windows는 맑은 고딕)을 사용합니다.
- **여러 리포트 일괄 다운로드**: 선택한 리포트를 PDF 파일 하나에 1건당 1페이지로 묶습니다. 리포트별 개별 파일(ZIP)은 제공하지 않습니다.
- **DB**: SQLite 단일 파일입니다. 동시 사용자가 많은 운영 환경이라면 PostgreSQL 등으로 옮기는 것을 권장합니다(SQL은 표준 문법 위주).
- **자동 알림**(마감 임박 메일 등)과 **SSO 연동**은 없습니다. D-DAY 는 화면에만 표시합니다.
